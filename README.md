# 盲人尋道｜JavaScript 應用版

用手機後鏡頭即時辨識前方的**行人、腳踏車、機車、汽車、公車、卡車**，判斷距離、速度與碰撞時間，並用深度估計找出**低垂樹枝、招牌、柱子**等頭部高度障礙物，以**語音、警示音與震動**提醒視障者。

所有辨識都在**手機瀏覽器裡執行**：不需要電腦運算，影像也不會上傳或儲存。這個資料夾是獨立的 JavaScript 程式，不需要其他資料夾的程式就能運作。

> **這個資料夾：`javascript應用版-test/webapp`**——只有這裡的檔案屬於 JavaScript 版。上一層的 `blindnav/`、`main.py` 等 Python 檔是 v4（`舊版/應用版(v4)`）的對照用副本，這裡完全不會用到；設定請改**本資料夾**的 `settings.json`，不是上一層那份。需要電腦執行辨識的 Python 版，請看 `網頁應用版`（區網、公開網址、雲端都有）。

## 給視障使用者：怎麼操作

開啟網頁後，**畫面上半部整塊都是「開始偵測」按鈕**，按一下就會聽到「正在啟動，請稍候」（使用 TalkBack／VoiceOver 時，它是畫面上第一個按鈕，點兩下啟動）。準備好時會聽到「準備好了，開始偵測」。

**請把手機直立固定在胸前，鏡頭朝前。** 手機明顯朝天或朝地超過 3 秒，系統會說「鏡頭朝向地面，請把手機立起來」或「鏡頭朝向天空，請把手機往下壓」，調好時說「方向好了」。

| 你會聽到 | 代表什麼 | 建議 |
|---|---|---|
| 「危險，正前方行人」 | 預測約 3 秒內可能撞上 | 放慢腳步 |
| 「停，正前方行人」 | 預測約 1.5 秒內會撞上 | 立刻停下 |
| 「左前方，行人很近」 | 擋在行走路徑上且很近；一直沒有更靠近時會愈說愈少，警示音 8 秒後停 | 確認方向 |
| 「正前方，頭上有障礙」 | 導盲杖碰不到的樹枝、招牌 | 停下確認 |
| 「警報解除」 | 剛才的危險已經結束 | 可以繼續走 |
| 嗶聲（戴耳機時從物體那一側傳來） | 越急越近，長音最近 | 不必等語音就知道方向 |
| 每 10 秒一聲輕音 | 系統正常 | |
| 兩聲往下的低音，一直重複 | **暫時沒有偵測**（持續時會說明原因） | 先停下確認 |
| 「畫面全黑，鏡頭可能被擋住」 | 手指或包包擋住鏡頭 | 移開遮擋物 |

從旁邊經過、不會撞到你的人車**不會**讓系統出聲，這是刻意的設計：警示太多，真正危險時反而沒有人會理它。

| 操作 | 方式 |
|---|---|
| 想知道前方有什麼 | 按畫面下方的大按鈕「目前狀況」，或直接按影像、狀態列（例如「偵測到 2 個物體。正前方行人，約 3 公尺，正在靠近；左前方椅子，約 5 公尺。」） |
| 停止偵測 | 按兩次「停止」（走路時誤觸不會突然失去保護） |
| 調整語速 | 開始畫面的「語速」按鈕：慢／正常／快／很快，手機會記住 |
| 關閉聲音 | 「聲音」按鈕；關閉後只有「停」還會念（iPhone 網頁不能震動，按下時會說明） |
| 只要嗶聲不要語音 | 開始畫面的「提示」按鈕 |
| 重聽說明 | 「語音說明」按鈕 |

系統也會主動用語音告訴你：載入進度、相機權限問題（包含下一步怎麼做）、鏡頭中斷與恢復、光線不足、鏡頭被擋住、偵測變慢、切換到別的 App 而暫停、手機電量低（20%／10%／5%，Android）。系統的問題只說明狀況，不會命令你改變走路方式。

> 本系統是**輔助**工具，看不到地面的坑洞與高低差，**請繼續使用導盲杖或導盲犬**。沒有警報不代表安全。

## 怎麼架設（不用會寫程式）

### 方法一：在電腦上先試試看
1. 雙擊 `啟動網頁版.bat`。
2. 瀏覽器會自動開啟 `https://localhost:8444`（沒有開的話請手動輸入這個網址）。
3. 出現「連線不安全」時，按「進階 → 繼續前往」（這是自己產生的憑證，可以放心）。
4. 按「開始偵測」並允許使用鏡頭。

### 方法二：用手機（手機和電腦連同一個 Wi-Fi）
1. 雙擊 `啟動網頁版.bat`。
2. 用手機相機掃描黑色視窗裡的 QR code。
3. 出現「不安全」警告時選「繼續前往」，按「開始偵測」並允許相機（iPhone 還會詢問「動作與方向」，請允許）。手機連不上時：Windows 防火牆詢問要按「允許」；學校或公共 Wi-Fi 常禁止裝置互連，可以改連手機熱點，再重新開啟程式。
4. 電腦只負責把網頁傳給手機，**辨識是在手機上跑的**。

> 方法一、二需要電腦裝有 Python 與 `cryptography` 套件（`pip install cryptography qrcode`）。
> 網站伺服器不會提供 `web_cert` 資料夾內的憑證私鑰下載。

### 方法三：放到網路上，手機隨時都能開（不需要電腦）
手機瀏覽器只允許 `https` 網址使用鏡頭，最簡單的免費做法是 **GitHub Pages**：
1. 到 [github.com](https://github.com) 建立一個新的公開儲存庫（repository）。
2. 按「Add file → Upload files」，把這個資料夾**裡面的東西**拖進去（`index.html` 要在最外層），按「Commit changes」。**不要上傳 `web_cert` 資料夾**，裡面有憑證的私密金鑰（公開網站也用不到它）。
3. 到儲存庫的「Settings → Pages」，Branch 選 `main`、資料夾選 `/ (root)`，按 Save。
4. 等一兩分鐘，頁面上會出現網址（例如 `https://你的帳號.github.io/儲存庫名稱/`），用手機開啟即可。

> 第一次開啟要下載約 51 MB（辨識模型 11 MB、深度模型 19 MB、執行環境 21 MB）；iPhone 與沒有顯示晶片加速的手機約 22 MB（不跑深度模型，頭上障礙不會提醒），全部從這個網站本身下載，不需要連外部網站。建議連 Wi-Fi，下載時會用語音報進度，網路中斷會自動接著下載。第一次開啟時網頁會自動重新整理一次，這是為了啟用多執行緒。之後會存在手機裡（`sw.js`），**出門沒有網路也能重新開啟**。可以用瀏覽器的「加到主畫面」，之後像 App 一樣開啟。
>
> 用方法一、二的自簽憑證網址時，瀏覽器不允許離線快取，需要電腦一直開著；要離線使用請用方法三的正式 https 網址。

## 功能
- **三段式距離警示**：綠（較遠）→ 橙（偏近）→ 紅（過近），門檻依物體實際大小調整。
- **速度偵測**：朝使用者衝過來（畫面面積變化率）與從面前快速橫越（橫向速度）都會提醒。
- **只在會撞上時才提醒（報告的核心）**：推算幾秒後會撞上（TTC），並判斷會不會進入使用者的行走路徑。從旁邊經過、正在遠離、遠處橫越的人車，再近、再快也不出聲。
- **語音分兩級**：約 3 秒內念「危險」，約 1.5 秒內念「停」（`TTC_URGENT_SEC` 設 1.8，已補償實測約 0.3 秒的延遲）；危險結束 3 秒後念一次「警報解除」。「停」攸關安全，聲音關閉時也會念。
- **TTC 沒有系統性偏晚**：對 `1/框高` 做回歸（等速趨近時它是嚴格的直線），不會把 3 秒算成約 4 秒；框高被畫面切掉時改看框寬與物體上半部（報告「未來展望二」）；近到上下都超出畫面、量不到變化時，照最後的 TTC 繼續倒數。
- **手機不夠快時自動調整**：iPhone 與只有 CPU（WASM）的手機改用只偵測、不算輪廓的 320 輸入模型（實測快 1.66 倍、命中率沒有變差）、開多執行緒（iPhone 為避免記憶體不足維持單執行緒）、更頻繁偵測、關閉深度模型，並用語音說明警報可能較晚（報告實驗四）。顯示晶片執行中出問題時，自動改用 CPU 繼續。
- **穩定追蹤**：ByteTrack 兩階段配對；偶爾漏抓一兩次時用預測位置暫留，追蹤編號不變。
- **頭部高度障礙**：Depth Anything V2 深度估計找出樹枝、招牌、柱子（在背景執行緒運算，約每 0.7 秒一次）；鏡頭被擋住時不判斷，不會誤報。
- **只偵測路上合理的東西**：行人、腳踏車、機車、汽車、公車、卡車、狗、貓；椅子、長椅、桌子、盆栽、消防栓、行李箱、停車收費器一律說「障礙物」。馬桶、床、沙發、飛機、背包、手機等完全不偵測。
- **減少認錯**：信心不夠高要連續看到 3 次才算，極小的框與「在天上的地面物體」不算；開始前用一張已知照片檢查顯示晶片的結果，不對就改用 CPU。
- **畫面順、沒有幽靈框**：畫面是鏡頭的即時影像，不被辨識速度拖慢；每幀都真的辨識，這一幀沒看到的物體不畫、也不發警報；手機轉得太快時先不畫框。
- **多線索測距**：比例法、針孔公式、深度圖依可靠度加權，被擋住或被畫面切掉時自動改用可信的方法。
- **鏡頭晃動補償**：手機陀螺儀＋背景位移比對，從物體速度中扣掉鏡頭轉動。
- **倒車雷達警示音**：只有一種聲音，越近越急促，很近時變長音；戴耳機時聲音從物體那一側傳來；語音播放與聲音關閉時仍會震動（Android）。
- **一次只念一句、不搶話**：同時有好幾個警報時，只念最緊急的一句；已在喊「危險」的物體不再多念「很近」，判定閃爍不會重喊。
- **不嘮叨**：同一個近物的提醒間隔由 5 秒逐次加倍到 60 秒，8 秒沒有更靠近就停掉警示音，又靠近或有新物體時立刻恢復；光線不足最多 5 分鐘提一次，偵測變慢持續 10 秒才說。
- **狀態提示**：系統正常時每 10 秒一聲輕音；暫時沒有偵測時有專屬提示音，持續才語音說明，真的恢復才說「偵測已恢復」。
- **語音試聽與操作說明**：開始前可確認語音並實際示範三種提示音，偵測中可按「語音說明」重聽。
- **為看不到畫面的人設計**：主要按鈕放大並排在最前面，所有狀態都有語音，可隨時詢問「目前狀況」，提醒手機沒扶正與電量過低，停止要按兩次，語速可調。

## 除錯用的診斷紀錄
辨識一律在手機上執行，影像與聲音都不會離開手機。只有用「方法一、二」連到**自己區網的電腦**時，手機會把錯誤訊息與數字（手機型號、幀率、偵測到的類別與座標、念了哪句話）傳給那台電腦，存在 `web_cert/phone_log.txt`，方便找出實機的問題；放到公開網站時不會傳送任何東西。

## 調整參數
用記事本編輯 `settings.json`，存檔後重新整理網頁即可生效。`js/config.js` 裡任何一個大寫設定都可以覆寫，例如：
```json
{ "PROXIMITY_RED_RATIO": 0.3, "TTC_DANGER_SEC": 2.5 }
```
名稱打錯或型別不符時會略過，不會讓網頁壞掉。手機跑得太慢時可以試試 `"DEPTH_ENABLED": false`（關閉頭部高度障礙偵測，速度會快很多）。

## 測試
啟動網站後開啟 `/tests/index.html`，會執行 80 多項自動測試（距離／速度分級、TTC、警報規則、深度圖障礙、晃動補償、追蹤器、設定檔驗證，以及依作品說明書驗證的：正面走來一定判定會撞上、錯身與遠處橫越不出聲、TTC 回歸沒有落後、截斷補償、「危險→停」升級、不搶話、直拿手機的焦距、預測幀不算樣本）。
網址加上 `?model=1`（例如 `https://localhost:8444/tests/index.html?model=1`）會再用真實模型辨識公車照片，確認能找到行人與公車、漏抓後追蹤編號不變。

### 情境模擬結果（2026-11-04，最終版）
真人去背後依針孔相機幾何合成影片，用無頭 Chrome 的假鏡頭跑完整流程（WebGPU，電腦的速度，不代表手機）；語音發出當下從畫面讀幀編號，換算真實的「離撞上還有幾秒」。每個情境重複 4～6 次，範圍是最小值～最大值。**這是合成影像，只能抓程式錯誤，不能取代實地測試，也不是報告的實驗數據。**

| 該響的情境 | 「危險」時剩幾秒 | 「停」時剩幾秒 |
|---|---|---|
| 正面走來 1.5 m/s | 2.87～2.90 | 1.60～1.67（3 次中 1 次 0.77） |
| 慢走 0.7 m/s | 2.32～2.36 | 1.66～1.86 |
| 跑步 4 m/s | 2.68～2.95 | 1.48～1.68 |
| 斜向走來 | 2.63～2.73 | 1.40～1.90 |
| 多人，只有一人會撞 | 2.73～2.90 | 1.50～1.60 |
| 手機晃動中走來 | 2.80～3.07 | 0.97～1.27 |
| 手機直拿（480×640）走來 | 2.77～2.87 | 1.67～1.73 |
| 手機直拿且晃動 | 2.67～2.87 | 1.63～1.70 |
| 在 3 公尺處突然出現 | 1.73～1.87 | 1.33～1.57 |

不該響的情境，都沒有喊「危險」或「停」：從旁走過、遠處橫越、多人都錯身、走到一半停下、遠處站著、晃動中站在路邊、手機直拿時錯身、晃動中的靜態街景。站在 2 公尺外不動時只念「很近」，提醒會愈來愈少。

人多的畫面（來回播放、沒有人會撞上）：6 人與 15 人的合成畫面都沒有喊「危險」或「停」。

**底層比對：** 60 張真實街景，手機版程式與官方 Ultralytics 的結果一致（WebGPU：一致 264 個、多出 0 個，信心平均差 0.005，框 IoU 0.97）。前處理、解碼與座標轉換沒有算錯。

**真實走路影片（3 支街景影片各 70 秒，放慢 2 倍接近走路速度，沒有陀螺儀資料）：** 找到並修正了合成測試看不到的問題：框留在沒有東西的地方（幽靈框）、畫面與框錯開、鏡頭上仰時最下緣的人頭被當成很近。修正後截圖裡的框都貼在實際物體上。警報在安靜的街道很少（一支約 80 秒 2 句），車多人多的路段仍多（約 80 秒 9 句），其中有多少是誤報沒有逐一標註，要實地確認。

**真實照片的誤判（202 張天空、樹木、電線、建築）：** 單張判斷時，新規則留下的偵測約為舊規則的一半（448 模型 52→23 個、320 模型 37→21 個），其中有些是照片裡真的有的東西。

## 已知限制
- **尚未在真實手機、真實街道與視障者身上測試**：自動測試用的是合成影像與假鏡頭，實際的語音、震動、iPhone 權限流程與戶外效果都需要實地確認。
- **頭部高度障礙的準確度尚未以真實障礙物驗證**：門檻只用少量影像校準，而且深度模型已換成 q4f16，實際的漏報與誤報都要實地測試後調整 `settings.json` 的 `STATIC_NEAR_RATIO`。
- 速度取決於手機：有 WebGPU 的手機較快；沒有的可能每秒只有 1～3 幀（模擬值，未經實機確認），持續低於每秒 3 幀時會語音說明警報可能較晚。
- 人很多又很密集時仍可能誤報，手機越慢越明顯（數據見上方情境模擬）。
- 只認得模型訓練過的類別；認不得的障礙物靠深度圖，不保證都抓得到。看不到地面的坑洞與高低差。
- 背景位移比對只量得到整體平移（鏡頭左右、上下轉動）；有陀螺儀時以陀螺儀為主。
- 遮罩在 112×112 的解析度上計算，邊緣較粗。
- 公尺數是估計值，假設鏡頭大致水平。
- iPhone 螢幕鎖定或切換 App 時鏡頭一定會停止，也不支援網頁震動。

> 本系統僅提供輔助提示；未發出警報不代表前方安全，請勿只依賴本系統判斷周遭環境。
