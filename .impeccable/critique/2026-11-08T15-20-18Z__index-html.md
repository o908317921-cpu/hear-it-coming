## Design Specificity Verdict

互動設計完全為這個產品量身打造；視覺外觀是通用的暗色青綠儀表板套件。開眼睛圖示對全盲使用者的產品來說是奇怪的選擇；「聲音優先」「碰撞雷達」只存在於文字裡。

Deterministic scan：CLI 2 個警告（low-contrast `.fineprint` 3.0:1 對漸層最亮處；dark-glow `#startBtn` 青綠色陰影）。瀏覽器內偵測 0 個。low-contrast 在實際位置約 4.6:1，勉強過關，屬半個誤報，但這段是最重要的安全聲明卻最小最暗。

## Priority Issues

- [P1] 「失去保護」看起來像普通警告 — app.js:296/298 用 wait/warn；修正：鏡頭中斷、辨識卡住改用 `.pill.bad` 與獨立的 `#banner.lost` 樣式，文字語音不變。harden + colorize
- [P1] 電腦端的協助者路徑被埋住且不完整 — `.qr` 沒有 QR 圖片，只有網址文字，而且排在最底下；修正：本機產生 QR，在 hover/pointer:fine 時用 CSS 移到開始按鈕旁，手機 DOM 順序不變。onboard / layout
- [P2] 手機 375×812 偵測畫面，固定的 `.controls`（194px）蓋住第三個儀表「行人距離」；`#notice` 空白時留約 36px 空洞；修正：`:empty` 收合、儀表壓縮成一條，按鈕不動。layout / distill
- [P2] 警報高峰的層級衝突 — 實心青綠 `#sceneBtn` 和紅色 `#banner.red` 搶視線；修正：警報時降低 sceneBtn 視覺重量，大小位置不變。quieter
- [P3] `#voiceBtn` 的 🔊 和 `#stopBtn` 的 ■ 會被讀螢幕念出；修正：改成 aria-hidden 的圖示，讀出的名稱不變（需確認符合 PRODUCT.md 的 aria 不變原則）。audit

## Persona Red Flags

- Sam（讀螢幕）：流程扎實；emoji／■ 雜音；開始後焦點跳兩次，需實機測。
- Casey（行動中）：按鈕都 ≥64px；停止在右下角最容易誤觸，但有按兩次保護。
- 科展評審：分不出「沒有保護」和「光線暗」；手機上看不到第三個儀表；TTC、速度指數、刻度沒有說明；FPS 只是右上角小灰字。
- 明眼協助者：電腦上沒有 QR；語速選項看不到全部；偵測中不能改設定。

## Questions to Consider

1. 畫面主要給評審看，偵測時要不要有「展示模式」：更大的影像、有圖例的儀表、明顯的 TTC 讀數？
2. 給盲人用的產品為什麼用眼睛當標誌？聲音或雷達的識別會說出什麼？
