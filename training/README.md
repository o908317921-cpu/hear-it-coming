# 訓練行人號誌與斑馬線模型

原本的 YOLO 是用國外照片訓練的，認不得台灣的 LED 小綠人、小紅人，斑馬線也只靠手寫規則（街景照片只認出 16%）。
這裡訓練一個**另外的小模型**，只認三種東西。原本偵測行人、車輛的模型完全不動，碰撞判斷不受影響。

| 編號 | 類別名稱 | 是什麼 |
|---|---|---|
| 0 | `ped_green` | 亮著的小綠人（有沒有倒數都算） |
| 1 | `ped_red` | 亮著的小紅人 |
| 2 | `crosswalk` | 行走方向前方地面上的斑馬線 |

> 類別的**順序和名稱**要跟上表一模一樣。訓練筆記本會檢查，不一樣就停下來。

整個流程：**拍影片 → Roboflow 切成照片並標註 → 匯出 → Colab 訓練 → 下載 `signals-yolo11n-320.onnx`**。

---

## 1. 拍攝

用 iPhone **錄影**，拿在胸前、鏡頭朝前，就像實際使用時一樣。視角跟實際使用一樣是最重要的事。

- **每一類至少 300～500 張**（切照片之後算）。
- 要涵蓋：白天、傍晚、晚上、雨天、逆光；近（5 公尺）、中（10～15 公尺）、遠（對街）。
- **一定要拍「沒有號誌」的畫面**：車尾燈、紅色招牌、綠色招牌、樹、手扶梯、樓梯。這些照片不用框任何東西，用來教模型「這些不是號誌」，誤報才會少。數量約佔全部的 2～3 成。
- 每一段影片的檔名寫上**路口名稱**，例如 `中正路_民生路_晚上.mov`，等一下分資料時要用。
- 安全第一：拍攝時有人陪同，不要站在車道上。

## 2. 分成三份資料（最重要的一步）

| 用途 | 比例 | 來源 |
|---|---|---|
| 訓練 train | 約 70% | 大部分路口 |
| 驗證 valid | 約 15% | 跟訓練同一批路口 |
| 測試 test | 約 15% | **完全沒在訓練裡出現過的路口** |

測試照片**不能**跟訓練照片來自同一個路口，也不能從同一段影片切出來。
同一段影片相鄰的兩張幾乎一樣，混在一起，模型等於提前看過考題，準確率會假性偏高。
做法：選 2～3 個路口只拿來當測試，上傳到 Roboflow 時直接指定到 **Test**。

## 3. 在 Roboflow 標註

1. 到 roboflow.com 註冊（免費），建立專案，類型選 **Object Detection**。
2. 類別依序建立：`ped_green`、`ped_red`、`crosswalk`。
3. 上傳影片時，Roboflow 會問要每秒切幾張：**每秒 1～2 張**就好，太多會有一堆幾乎一樣的照片。
4. 上傳時選分配方式：一般路口選 **Train/Valid 自動分配**，測試路口選 **Test**。

### 怎麼框

| 類別 | 框什麼 | 不要框 |
|---|---|---|
| `ped_green` | 亮著的小綠人那一格面板（只框小人那格，不含上面的倒數） | 沒亮的燈；車用的綠燈 |
| `ped_red` | 亮著的小紅人那一格面板 | 車用的紅燈、車尾燈 |
| `crosswalk` | 你行走方向前方、地面上看得到的白色條紋整片 | 側邊橫向的斑馬線（不是你要走的方向）；停止線 |

- 同一張照片有好幾個號誌，每個都要框。
- 號誌太小、看不清楚顏色的（小於約 10 像素）就不要框，也不要刪掉照片。
- 框要貼緊，不要留太多空白。
- 不確定的照片，在 Roboflow 加上標籤 `unsure`，之後再一起討論，不要隨便標。

## 4. 匯出

在 Roboflow 按 **Generate New Version**：
- **Preprocessing**：Auto-Orient 打開，**Resize 不要開**（訓練程式自己會縮放）。
- **Augmentation**：全部不要開（訓練程式自己會做）。

再按 **Export Dataset**，格式選 **YOLOv11**（或 YOLOv8，兩種一樣），選 **Download zip**。
解壓縮後長這樣：

```
資料集/
├── data.yaml
├── train/
│   ├── images/   照片
│   └── labels/   每張照片一個 .txt，裡面是框的位置
├── valid/
│   ├── images/
│   └── labels/
└── test/
    ├── images/
    └── labels/
```

把整個 zip 檔改名為 `signals-dataset.zip`，上傳到 Google 雲端硬碟的 `科展/` 資料夾。

## 5. 在 Colab 訓練

1. 打開 colab.research.google.com，選「上傳」，上傳這個資料夾裡的 `train_signals.ipynb`。
2. 上方選單 **執行階段 → 變更執行階段類型 → T4 GPU**。
3. 從上到下一格一格按執行（或「執行階段 → 全部執行」）。
4. 約 30～60 分鐘後（看照片數量），最後一格會下載 `signals-yolo11n-320.onnx`，並把結果圖存到雲端硬碟。

## 6. 結果要看什麼（寫進科展報告）

筆記本最後會用**測試路口**的照片算出每一類的數字：

| 指標 | 意思 | 對這個系統來說 |
|---|---|---|
| Precision（精確率） | 模型說「有」的裡面，真的有的比例 | **最重要**。說錯號誌比不說更危險，目標 ≥ 0.95 |
| Recall（召回率） | 真的有的裡面，被找出來的比例 | 越高越好 |
| mAP50 | 綜合分數 | 跟別人的模型比較時用 |

會一起存下來的圖：混淆矩陣（哪一類常被認成哪一類）、PR 曲線、訓練過程曲線。

**跟手寫規則比較**：同一批測試照片，可以再用 `tests/field.html` 的方法跑一次現在的顏色規則（`js/scene.js` 的 `pedestrianSignals`），兩者的精確率、召回率放在同一張表，就是一個完整的實驗。

## 7. 換進 App（之後再做）

訓練好的模型只有 3 類，App 目前讀模型的程式（`js/yolo.js`）是照 80 類寫的，**不能直接替換**原本的模型。
要另外加一段程式：在原本偵測之外，每秒跑一兩次這個小模型，結果交給 `js/scene.js` 決定要不要念。拿到 `.onnx` 檔之後再接上。

## 用自己電腦訓練（備案）

這台電腦有 NVIDIA RTX 2050（4 GB），也可以在本機訓練，但要自己裝環境，而且 Python 3.14 不一定支援所有套件。
建議另外裝 Python 3.12，再執行：

```
pip install ultralytics
yolo detect train data=資料集/data.yaml model=yolo11n.pt imgsz=320 epochs=100 batch=8 patience=20 seed=0
```

`batch=8` 是因為顯示卡記憶體只有 4 GB；出現 out of memory 時改成 4。
